The message bubble

The field is styled as a chat message. It is built like TextBox: the value is held by a hidden field of the form, the typing is done by RichEditor. The formatting toolbar with emoji insertion is shown above the bubble on focus, Enter starts a new paragraph instead of submitting the form. 


			

		

	


	

		
With a ready value

		

			The value is stored as messenger markup rather than HTML: **bold**, _italic_,
			~strikethrough~, __underline__. Enter gives one line break
			(\n), two presses give an empty line (\n\n). The spintax
			[one|two] and the properties {NAME} are highlighted in the text but go into the value
			as they are: the highlighting is ordinary spanwhich serialization drops.
		

		

			

				
				

			

		

	


	

		
Properties from the markup

		

			Personalization is off by default: without it there is neither a toolbar button nor highlighting. It is turned on by
			the option personalization, the attribute data-personalization or by the declaration of
			the property list itself, which is how it is on in every field of this page. The list may be
			declared by the attribute instead of the options:
			data-variables of the value element, for markup given by a server. Two forms: keys separated by commas
			(data-variables="NAME, CITY") or a JSON array when the properties have names. A list given
			in the options wins over the attribute. The second field has no properties at all, and the text in its window
			is set by the attribute data-variables-empty: the reason for an empty list is known to the application. There too is
			the setup link as the last line of the window: the option variablesSetup takes a function
			(an SPA navigation or a window of your own; a stub here), and as a string it would be the address of an ordinary link, which can be
			declared by an attribute as well data-variables-setup.
		

		

			

				
				

			

			

				
				

			

		

	


	

		
New properties

		

			By default the list is closed: a key outside it is an error of the value, the property is marked red
			and stops the form from being submitted (the first field). The attribute data-new-variables (the option
			newVariables) opens the list: such a key becomes a request for a property that
			an external system will create (the second field). It is marked with its own colour, does not hold the submit back, and in the
			personalization window it stands as an entry marked "new", from where it can be inserted again. A click on the
			property itself opens the key editor: there is nothing to choose from, it was typed right here. The key is raised
			to upper case, and at its edges only a letter, a digit or an underscore is allowed. What is left to
			create is given by the property unknownVariables, printed under the field.
		

		

			

				
				

			

			

				
				

			

		

	


	

		
A quote and a code block

		

			Blocks are off by default, not every channel understands them. Here they are declared by the attribute
			data-blocks="quote code". Monospace and the code block share one button: with
			one line or a part of it selected it is monospace, with several lines (or nothing selected) it is a block.
			Enter inside a block ends it,
			Shift+Enter breaks the line inside it, Backspace at the start of a block returns plain
			text. In the value a quote is > at the start of every line, and a code block is a fence
			of three backticks; inside the code the markup is not parsed and the indents are kept.
		

		

			

				
				

			

		

	


	

		
Showing the output

		

			The switch above the bubble shows the value the way it goes into the form, as messenger
			markup. By default there is none: whoever writes a message does not need the raw markup. It is turned on by
			by the option source or by the attribute data-source. The panel is shown instead of
			the bubble and only shows: its text can be selected and copied, while the message is still edited
			in the bubble.
		

		

			

				
			

		

	


	

		
States

		

			required, readonly and disabled are taken from the value element, as in
			the rest of the kit controls. The button checks the validation of the form.
